# Dragon Writer

工具无关的长篇虚构小说写作工作流。当用户需要创建一本书、续写一章、重建或阅读大纲 / 设定文件、导入已有章节、调整故事方向、修订某一章，或在多个会话间维护持久的故事圣经 / 状态时使用本 skill。

本 skill **不设置题材、受众、内容范围或表达尺度的白名单 / 黑名单**。`genre` 只用于选择更合适的叙事技法与审计视角，绝不用于拒绝、删改或缩窄用户选择的题材；作者明确给出的创作边界仍按项目意图保存。宿主平台自身规则不写入小说质量审计，也不伪装成题材规则。

## 不可违反规则

- **文件优先**：把既有的大纲、设定、角色、规则、章节、状态文件视为权威，一切从文件出发。
- **不覆写 canon**：除非用户明确要求改写，否则不改写作者已成文的内容；拿不准时追加带日期的备注，而非直接重写。
- **静态基础与运行时态分开**：Foundation（前提、世界法则、卷章地图、角色卡稳定属性、规则书）只在用户明确要求或方向性转向时修改；Runtime（当前状态、钩子、摘要、焦点、审计漂移、道具账本、空间锚点、角色卡物理/逻辑数据时间线）每章更新（时间线为追加式：只加变化点行、不改旧行）。
- **单写手串行**：连续写作、续写、多章修改期间只能由主代理规划、起草、改写正文和更新 Runtime。禁止子代理写正文、补片段、改段落、提前写后章或维护状态；第 N 章未封板为 `closed`，不得开始第 N+1 章。
- **子代理只做无背景冷读**：只有草稿冻结并通过机械门禁与主代理知情审计后，才可启动一个全新的审计子代理。它只能报告读者可见问题，不得改正文；同一时刻最多一个，不得复用旧审计上下文。
- **报告具体创建或变更了哪些文件**：不要声称某个章节或某本书"已经存在"，除非文件真的被写入了。

## 更新（默认只读，不自动应用）

`_meta.json` 默认 `update.auto_check=false`。普通写作不联网、不下载、不替换 skill；需要时可只读查询版本，应用更新必须由用户明确要求。

```bash
python scripts/auto_update.py status --verbose   # 只查远程版本，不下载
python scripts/auto_update.py check --force      # 用户明确要求更新时才检查并应用
```

- `status` 不修改本地文件。
- `check --force` 会修改 skill，只能在用户明确授权更新时运行。
- 下载包应用前仍须通过 git 工作树保护；更新不是写作流程的启动步骤。

版本号规则：语义化版本 `x.y.z`（如 `3.2.0`）。本地版本 < 远程版本才执行更新；本地无 `_meta.json` 或无 `version` 字段视为需要更新。远程版本来源：`https://api.skillhub.cn/api/v1/search?q=d-writer`（slug=`d-writer`）。

> **完全禁用更新能力**：编辑 `_meta.json` → `update.enabled: false`。

## 从这里开始

1. **识别模式**：
   - **模式 A · 新书**：用户给了一句灵感、书名、题材，或要求写一本新小说 → 读 `references/workflow-new-book.md`。
   - **模式 B · 续写**：存在大纲 / 设定 / 章节 / 状态文件 → 读 `references/workflow-continue.md`。
   - **模式 C · 导入 / 续写**：手里有旧章节，但状态文件很弱或缺失 → 读 `references/workflow-import.md`。
   - **模式 D · 转向 / 修订**：换方向、改写、修补，或从特定位置续写 → 读 `references/workflow-redirect.md`。
   - **模式 E · 改写 / 修复**：重写某一章 → 读 `references/workflow-rewrite.md`。
   - **模式 F · 仪表盘**：看进度、打开仪表盘、看完成度、人物关系或读章节 → 读 `references/workflow-dashboard.md`。
   - **模式 G · 合并审核**：写完一章或连续写完多章后，把选定章节合并统一审核 → 读 `references/workflow-combined-audit.md`。
2. 动任何文件之前先读 `references/file-contract.md`（文件职责、兼容命名、权威顺序、Foundation / Runtime 边界）。
3. 新书或基础文件缺失时读 `references/templates.md`（全部基础文件模板）。
4. **续写或改写章节正文前**读 `references/chapter-craft.md`（戏剧单元、叙事时间压缩、信息 / 关系权限、章首入戏与断章技法）。
5. 续写、改写、导入或回滚前读 `references/chapter-protocol.md`；质量维度再读 `references/audit-dimensions.md`。

## 章节串行事务与三道质量门

每章都是一个不可并行、哈希绑定的事务：`prepared → drafted → gated → audited → closed`。状态只允许由 `scripts/chapter_txn.py` 推进；intent、草稿、字数契约、重复报告、两类审计、正式稿、状态账本、索引与章末快照均绑定到事件。只有完整 `closed` 才能准备下一章。长上下文时运行 `build_work_packet.py` 从磁盘重建当前章包，不增加写手。

**三道门为强制环节，任何写作任务都不得跳过**：
- **机械门禁**：用统一字符算法检查硬字数下限，并核验 intent 中每个必要场景节点都存在正文证据；未通过不得启动冷读、落正文或更新索引。
- **知情连续性门禁**：由主代理对照项目文件检查时间、空间、信息获知、关系权限、道具、数字、钩子、章际衔接与跨章新意。需要隐藏事实的维度不得外包给冷读者。
- **无背景冷读门禁**：由一个全新的子代理只阅读正文，检查阅读体验、节奏、突兀知情感、关系体感、重复、语言与去 AI 味。子代理只提问题，不修改正文。
- **连续写作逐章封板**：同一轮写多章时也必须逐章完成全部门禁，不得并行起草、交叉改写、合并省略或让任何代理提前处理后章。
- **反偷懒硬门**：`book.json.chapterMinChars` 是不可被章节意图下调的书级下限；每个必要场景节点必须绑定当前草稿哈希、确定段落范围和可精确命中的短引。字符数或描写职责不达标时，只补缺失的戏剧工作并重跑门禁，不用复述、同义改写或景物堆砌注水。
- 未当场修复的发现必须落 `audit-drift.md`，不存在"先记着、后面补"的静默跳过。

### 主代理知情初筛（12 点，每章必过）

- 本章是否围绕一个可说清的戏剧问题组织，并让至少一个具体压力、关系、线索、目标或钩子发生了不可互换的改变。
- 主角的行为是否符合既定的动机与当前约束。
- **★ 信息权限**：每个角色说出、想到或据以行动的事实，都能在「章节感知事实表」找到该角色的获知路径、获知章与正文证据；同场出现不等于共享全部信息，作者知道 / 读者知道也不等于角色知道。
- **★ 关系权限**：称呼、玩笑、托付、身体接触、秘密披露和默契程度不得超过「关系许可账本」已经建立的层级；任何突进都须有本章可见的催化事件与后效，初识角色不能凭空拥有旧识口吻或共同回忆。
- **★ 叙事时间与章节切分**：章节边界由戏剧问题、转折或后效决定，而非机械地覆盖一天；无有效冲突 / 选择 / 关系或信息变化的吃饭、赶路、睡觉等时段应概述或跳过。明确章首 / 章末故事时钟、耗时、跳时方式与落点方位。
- **★ 跨章新意**：对照近 5–10 章的情节指纹，本章必须写明新增量；相同目标—阻碍—行动链—结果仅换措辞重演，或换视角复述却没有新信息 / 新代价 / 新解释，视为致命重复。
- 资源、伤势、地点、时间、库存、关系状态与承诺是否与状态文件一致。
- 结尾让局面发生了真正的变化，而非只是烘托气氛或重复前文；且以断章技法收束（见 `references/chapter-craft.md`），不以总结 / 金句 / 宣布计划泄压。
- 文风是否符合既定的语言、体裁、视角、基调与篇幅目标。
- **★ 空间一致性**：场景方位 / 布局 / 人物相对位置是否与 `current_state.md` 的"空间锚点"兼容，移动路径必须经过中间空间，视角内不能看见隔墙背面。
- **★ 实体与常识**：随身物件、衣物、外貌特征的数量 / 存在 / 状态是否守恒；行为是否符合本书已经建立的物理、生物、因果与社会规则。架空例外以 `book_rules.md` 为准，不拿现实常识压制题材设定。
- **★ 章间衔接**：本章开场与上一章末尾的物理状态（谁在哪、什么姿势、穿什么、什么时间）显式衔接或有明确的时间 / 场景跳转标记；人物位置不得无交代地互换（对照 intent 的「前章末状态续接」字段）。
- 审计发现若未当场修复，必须落记录（`audit-drift.md`）。

初筛通过后才可冷读；初筛没过，由主代理修订并重跑机械门禁和知情初筛。

### 无背景冷读（子代理只审不改）

冷读的价值来自它不知道作者如何计划。必须使用不继承主代理对话的全新子代理；若平台支持上下文分叉选项，使用空上下文 / 不分叉。子代理不得调用写作、编辑或项目状态更新流程。

单章冷读包只含当前章节正文；章际冷读包只含上一章与当前章的正文，使用中性章节分隔。禁止附带大纲、意图、题材说明、人物卡、时间线、信息链、关系账本、状态、钩子、目标字数、作者解释、疑点提示、预期修法、旧审计报告或任何隐藏事实。审计规则只保留读者可见维度，不暗示哪里可能有问题。

流程：冻结正文 → 创建纯正文冷读包 → 全新子代理报告严重度、位置 / 短引、读者影响、修复方向 → 主代理结合完整项目状态修改 → 重跑三道门。可选二审也必须使用另一个全新子代理，只给修改后的纯正文和同一中性规则，不给一审报告。

分级落地：critical 必过、warning 修或留漂移记录、info 仅记录。未当场修复的发现必须落记录。**每章都创建权威章节意图 `chapter-NNNN.intent.json`；同名 `.intent.md` 只能由 `render_intent.py` 单向生成，禁止手改。**自由创作说明、正文和审计判断仍用 Markdown，不把小说写进 JSON。

### 合并审核（模式 G · 用户发起）

单章审计只覆盖"这一章内部"。**写作任务完成时**主代理**必须主动询问用户**："是否进入合并审核？"——**仅在任务终点询问一次**：单章写作（只写一章）在该章落盘并通过单章审计之后询问；**连续创作（一轮连续产出多章）只在最后一章完成后询问**，中途各章完成时不打断。用户决定**跳过**，或**进入并指定范围**（全部章节 / 部分章节 / 指定章节区间）。

- **定位**：让无背景编辑连续阅读选定正文，暴露章际断裂、读者可见的突兀知情 / 关系跳级、节奏同构、复述与语言模式重复。隐藏 canon、精确时间线、事实来源和权限账本仍由主代理知情审计。
- **执行**：只合并选定章节正文，使用中性分隔，不附 43 维全表或任何项目资料 → 一个全新子代理冷读并报告 → 主代理修改 → 重跑机械与知情门禁 → 未修复发现落 `audit-drift.md`。
- **规则**：子代理只能冷读报告；主代理负责所有事实判定、正文修改和状态更新。合并审核同样不得并行启动多个审计员。
- 详细流程：`references/workflow-combined-audit.md`。

## 平台说明

本 skill 刻意保持工具无关：无论哪个 agent，都使用其自带的文件与命令工具（Read / Write / Edit / Task 或等价能力）完成读写与执行。整个工作流依赖的是文件契约，而非某一款具体 CLI。
