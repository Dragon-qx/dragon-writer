# Dragon Writer 审计维度

本章定义续写 / 改写后使用的连续性审计维度（含 **41 个候选深化审计维度**，角色与人设、世界与体系、情节与钩子、节奏与阅读感、文风与技法、安全与合规、信息边界、同人专属、场景与空间、细节与道具、常识与逻辑共十一节）。每维给出：编号、名称（中英）、判定规则、默认分级、体裁覆写条件。标准表述：**9 项驻场初筛 + 41 个候选深化审计维度，按体裁和章节风险裁剪执行**。

## 何时使用、怎么用

- **默认**：模式 B（续写）每章落盘前、模式 E（改写）重写完成后，都跑一轮。
- **体裁裁剪**：不是本本都要跑满 41 维。按 `book.json.genre` 裁剪出本章要跑的清单——见"体裁覆写"列。默认中文长篇网文约激活 **20–24 维**（★ 标记的为默认激活）。
- **与 9 点 Chapter Quality Gate 的关系**：9 点初筛（SKILL.md 已有）是 **驻场初筛**，过不了直接改；通过后进入本 41 个候选深化审计维度作为 **深化审计**。两层是"初筛 + 深化"，不是二选一。
- **审-改循环**（见 SKILL.md 模式 B 步骤 6–7）：逐维过 → 出报告 → 对没过维度修订 → **回头从第 1 维再过一遍**（禁止只过"刚才没过的那条"）。
- **执行规则**：审计发现若未当场修复，必须落记录（`audit-drift.md`）——此规则不计入 9 项初筛，独立执行。
- **分级落地**：critical 必须修到 pass；warning 必须修或在 `audit-drift.md` 留"已知漂移 + 原因 + 计划"；info 仅记录。连跑 3 轮仍过不了的 warning，允许在 `audit-drift.md` 留记录后强制收工（防死循环）。

## 审计结果四态

审计结果使用**四态**，禁止二值化：

| 结果 | 含义 | 触发条件 |
| --- | --- | --- |
| **pass** | 维度检查通过 | 证据充分且无问题 |
| **fail** | 维度检查未通过 | 存在明确违规 |
| **not_applicable** | 体裁 / 场景不适用 | 体裁不匹配（如战力崩坏对日常向） |
| **unknown** | 缺少输入证据，无法判定 | 必要文件缺失或信息不足 |

**规则**：
- 缺少输入证据时**必须是 unknown**，不得判 pass。
- 体裁不适用时使用 **not_applicable**。
- 禁止因为文件缺失而判 pass。
- 每个 **fail** 必须附原文证据、影响和最小修复建议。

## 风险驱动审计

### 审计分层

审计按风险驱动，分为三层：

1. **每章固定 9 项硬检查**（驻场初筛，SKILL.md）：每章必过。
2. **每章体裁无关 critical 项**：维 27（敏感词）、维 32（读者期待）、维 33（备忘偏离）★ 始终激活；本章有空间 / 道具 / 动作描写时维 38 / 维 39 / 维 41 必须进清单。
3. **按章节标签激活的维度**：根据 `chapter_summaries.md` 的 `chapter_type` 激活空间、战斗、道具、感情、同人和时代等维度。

### 完整审计触发时机

- **每卷末、高潮、重大转向或用户要求时**：运行完整 41 维。
- **修订后**：重跑受影响维度及其依赖闭包，而非无条件重跑全部维度。
- **为本章审计清单记录激活原因和跳过原因**：在 `audit-drift.md` 中记录。

## 一、角色与人设

### 1. OOC 检查 / OOC Check
- **判定规则**：对照本维是"角色是否在情境驱动下行动"。同人模式下，canon 模式角色必须守住性格底色（参照 `fanfic_canon.md` 角色档案）；OOC 模式允许偏离但须仅记录不判定失败；AU 模式居中。参照角色档案的"欲望/恐惧/言行指纹"，无合理动机的行为翻转 = 问题。
- **默认分级**：warning
- **体裁覆写**：canon 同人 → **critical**；OOC 同人 → **info**（仅记录，不判定失败）；无档案时退化为 info。
- **结果四态**：pass（行为符合性格）/ fail（无合理动机的翻转）/ not_applicable（无同人模式）/ unknown（无角色档案时）。

### 25. 弧线平坦 / Arc Flatline Check
- **判定规则**：对照 `emotional_arcs` 与 `chapter_summaries`：主要角色在近期连续章节内是否始终停留在同一种情绪压力形态，没有经历"新压力 / 释放 / 转折 / 重估"。注意区分 **处境未变** 与 **内心未变**——前者可接受，后者是问题。
- **默认分级**：warning
- **文体覆写**：默认激活。无 `emotional_arcs.md` 时，用 `current_state.md` 的 `## Relationships` + 角色 `## Current State` 近似替代。

### 13. 配角降智 / Side Character Competence Check
- **判定规则**：关键抉择时刻，配角的行为是否被不合理地压低智商以成就主角。偶尔一次可接受；跨多章、跨多个配角同时降智 = 节奏与可信度问题。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 14. 配角工具人化 / Side Character Instrumentalization Check
- **判定规则**：配角是否只有"为推进主角剧情服务"的功能、没有自己的目标与动机。若干预多次出现，配角沦为任务物品而非人物。
- **默认分级**：info → 累计 3 例同配角 → 升级 warning
- **体裁覆写**：默认激活。

### 34. 角色还原度 / Character Fidelity Check（同人专属）
- **判定规则**：角色的语癖、说话风格、行为模式是否与 `fanfic_canon.md` 角色档案一致。偏离必须有情境驱动的合理解释。
- **默认分级**：warning（同人根级）；canon → **critical**；OOC → **info**
- **体裁覆写**：仅同人模式激活。

### 36. 关系动态 / Relationship Dynamics Check（同人专属）
- **判定规则**：角色之间的关系互动是否合理、是否与 `fanfic_canon.md` 中标注的关键关系一致，或有合理的发展弧线。
- **默认分级**：warning；cp 同人 → **critical**；其他同人 → warning
- **体裁覆写**：仅同人模式激活。

## 二、世界与体系

### 3. 设定冲突 / Lore Conflict Check
- **判定规则**：对照 `story_frame.md` 的"世界法则"、角色能力档案、`book_rules.md` 的"定局锁"、`current_state.md` 已知事实，检查新章是否违反已建立的设定。硬性数值冲突（能力、资源、地理信息）= 严重；软性语气偏差 = warning。
- **默认分级**：critical
- **体裁覆写**：默认激活。

### 4. 战力崩坏 / Power Scaling Check
- **判定规则**：对照角色能力档案 + `book_rules.md` 的"力量/资源/时间限制"：角色是否在没交代代价或升级路径的情况下突然变强/变弱。升级必须呼应"心障/外劫"设定，禁止"忽然顿悟"与"一拳秒杀"。
- **默认分级**：critical
- **体裁覆写**：★ 仙侠 / 修真 / 玄幻 / 升级流 → critical（核心）；日常 / 现实向 → 本维不激活。

### 5. 数值检查 / Numerical Consistency Check
- **判定规则**：金钱、物品数量、时间距离、兵力等数值在跨章时是否自洽。"300 下品灵石"、"三炷香"等具体数字需与之前引用一致。
- **默认分级**：warning
- **体裁覆写**：默认激活。有数值体系的体裁（系统、游戏、经营）→ critical。

### 35. 世界规则遵守 / World Rule Compliance Check（同人专属）
- **判定规则**：章节内容是否违反 `fanfic_canon.md` 中的世界规则（地理、力量体系、阵营关系）。
- **默认分级**：warning；canon → **critical**；OOC / AU → warning
- **体裁覆写**：仅同人模式激活。

### 12. 年代考据 / Era Accuracy Check
- **判定规则**：对照 `book_rules.md` 的"年代约束"（时代 + 地域）：称谓、器物、社会制度是否符合该年代。穿越/架空允许作者明示的设定跳跃。
- **默认分级**：warning
- **体裁覆写**：★ 架空 / 历史 / 古言 → 自动激活（`eraResearch` 或 `eraConstraints.enabled` 为 true 时）；现代 / 未来 / 架空-异世界体裁 → 不激活。

## 三、情节与钩子

### 2. 时间线检查 / Timeline Check
- **判定规则**：对照 `current_state.md` 的"地点与时间"、章节摘要的事件序列、角色证词：新章的时间顺序是否自洽，是否有"同一天发生不可能的事"或"年份/节令冲突"。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 6. 伏笔检查 / Hook Check
- **判定规则**：阅读 `pending_hooks.md` 账本，不要只看"有没有悬而未决的伏笔"，要读状态列中的 `stale / blocked` 标记、`core_hook`、`depends_on`、`promoted` 列，按下列规则升级：
  - **critical 仅适用于 `promoted=true`** 的伏笔。非升级的 stale/blocked 一律 info——`promoted` 是降噪开关，架构师阶段会产出大量非承重的种子。
  - `promoted=true` 且 `core_hook=true` 的伏笔 `stale (距>10)` → warning 升级为 critical。全书只有 3–7 条核心伏笔，任何一条漂移这么久都是烂尾前兆。
  - `promoted=true` 的受阻伏笔 `blocked on hook-X (阻>=6)` → warning。description 要引用 marker 字面 token 与上游 hook_id，让 Planner 安排落地路径。
  - 卷尾（`volume_map.md` 中任一卷的末章）仍有 `promoted=true`、`core_hook=true` 的伏笔处于 open/stale 且无显式"延至下一卷"规划 → critical。
  - `promoted=false` 的 stale 伏笔 → info 级记录，不判本章失败，但保留以便 Planner 安排清理。
- **默认分级**：按上述规则
- **体裁覆写**：默认激活。

### 24. 支线停滞 / Subplot Stagnation Check
- **判定规则**：对照 `subplot_board.md`（如有）与 `chapter_summaries.md`：是否有支线沉寂到接近被遗忘，或近期连续只被"重复提及、没有真实推进"。
- **默认分级**：warning
- **体裁覆写**：默认激活。无 `subplot_board.md` 时，用 chapter_summaries 的 `events` 列近似替代。

### 28. 正传事件冲突 / Mainline Canon Event Conflict（同人/番外）
- **判定规则**：番外事件是否与正典约束表 (`parent_canon.md`) 矛盾。
- **默认分级**：warning
- **体裁覆写**：仅 `parent_canon.md` 存在 **且** 非同人模式 → 激活。同人模式下由本条替换为同人专属维 34–37。

### 29. 未来信息泄露 / Future Knowledge Leak Check（同人/穿越）
- **判定规则**：角色是否引用了分歧点 (`fanfic_canon.md` / `parent_canon.md` 标注) 之后才揭示的信息。参照信息边界表。穿越/重生体裁需明确"哪些未来记忆可用"的硬性边界。
- **默认分级**：warning
- **体裁覆写**：仅 `parent_canon.md` 或 `fanfic_canon.md` 存在 → 激活；穿越/重生体裁自动激活。

### 30. 世界规则跨书一致性 / Cross-Book World Rule Check（番外）
- **判定规则**：番外是否违反正传世界规则（力量体系、地理、阵营）。
- **默认分级**：warning
- **体裁覆写**：仅 `parent_canon.md` 存在 → 激活（同人模式由维 35 替代）。

### 31. 番外伏笔隔离 / Spinoff Hook Isolation Check（番外）
- **判定规则**：番外是否越权回收正传伏笔——番外不该独立解决正传主线钩子。
- **默认分级**：warning
- **体裁覆写**：仅 `parent_canon.md` 存在 → 激活（同人模式由维 36 替代）。

## 四、节奏与阅读感

### 7. 节奏检查 / Pacing Check
- **判定规则**：检查节奏波形：最近 3–5 章是否形成了完整的「蓄压 → 升级 → 爆发 → 后效」周期？如果连续 5 章没有爆发（兑现 / 回报 / 翻转），标记为节奏停滞。如果上一章是爆发 / 高潮 / 大反转，本章是否写出了改变？如果直接跳到新蓄压而没有展示前一波爆发的影响，标记为「高潮后影响缺失」。非冲突章节中的日常 / 过渡 / 对话段落，是否至少承担了一项任务：埋伏笔、推关系、建立反差、准备下一轮蓄压——纯水日常标记为流水账风险。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 26. 节奏单调 / Pacing Monotony Check
- **判定规则**：对照 `chapter_summaries.md` 的章节类型分布：当近期章节长时间停留在同一种模式、把节奏压平，或回收 / 释放 / 高潮章节缺席过久时给出 warning。明确列出最近章节的类型序列。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 32. 读者期待管理 / Reader Expectation Check（★ 始终激活）
- **判定规则**：检查章尾是否重新点燃好奇心；已经承诺的回收是否按伏笔自身节奏落地；压力是否得到释放；读者期待缺口是在持续累积还是在被满足。如果刚经历高潮，检查后效章节是否在开启新周期前展示了具体改变。
- **默认分级**：warning
- **体裁覆写**：**体裁无关**——任何体裁都查，不裁剪。

### 33. 章节备忘偏离 / Chapter Memo Drift Check（★ 始终激活）
- **判定规则**：对照随章提供的章节意图（chapter-NNNN.intent.md）。成稿是否兑现了意图的 goal，并在各段正文中留下可见落地痕迹？任何段落缺失或被写反 → critical。**注意：稀疏意图合法**（喘息章可以只有 goal + 骨架 body），只检查意图实际写出的段落，不能因为意图稀疏就判 incomplete。
- **默认分级**：warning
- **体裁覆写**：**体裁无关**——任何体裁都查，不裁剪。

### 15. 爽点虚化 / Payoff Dilution Check
- **判定规则**：对照体裁的"爽点类型"（satisfactionTypes）：本章是否制造了情绪缺口（读者渴望释放）或完成了超出预期的兑现？只满足读者 70% 期待的兑现 = 爽点虚化。如果本章处于小目标周期的后效阶段，检查是否展示了具体改变——不只是情绪反应，而是地位、关系或资源的实际变化。
- **默认分级**：warning
- **体裁覆写**：★ 升级流 / 修真 / 爽文 → warning（核心）；无明确爽点体系的纯文学 → info。

## 五、文风与技法

### 8. 文风检查 / Style Check
- **判定规则**：对照 `style_guide.md`（或 `book_rules.md` 的"风格约束"）：文风是否与既定风格一致（古白夹杂 / 白话 / 半文半白）。是否出现作者不该有的现代语、表情符号、跨体裁混搭。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 9. 信息越界 / Information Boundary Check
- **判定规则**：对照 `current_state.md` 的"已知事实"与角色档案的"秘密/信息边界"：角色是否知道他们不可能知道的事？第三人称限制视角下是否泄漏了未被揭示的真相？叙事者的全知口吻是否突然跳到角色内心？
- **默认分级**：critical
- **体裁覆写**：默认激活。

### 10. 词汇疲劳 / Lexical Fatigue Check
- **判定规则**：对照体裁"高疲劳词"（fatigue words）清单：标记词是否过度集中。同时检查 AI 标记词（仿佛 / 不禁 / 宛如 / 竟然 / 忽然 / 猛地）密度——每 3000 字超过 1 次即 warning。`book_rules.fatigueWordsOverride` 优先于体裁默认。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 11. 利益链断裂 / Incentive Chain Check
- **判定规则**：关键剧情转折是否有合理的利益驱动；角色的决策是否符合其既定目标与约束。"为了剧情需要"而让人物放弃其核心利益 = 问题。
- **默认分级**：warning
- **体裁覆写**：默认激活。权谋 / 商战 / 宫斗体裁 → critical。

### 16. 台词失真 / Dialogue Authenticity Check
- **判定规则**：对照角色档案的"言行指纹"：语癖、句式、口头禅是否符合人设。角色是否说了不符合其身份/教育背景/当下情绪的话。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 17. 流水账 / Chronicle Drift Check
- **判定规则**：章节是否在按时间顺序罗列平淡事件，没有冲突、没有抉择、没有悬念推进。参照维 7 的"日常/过渡段落必须承担一项任务"规则：若无任何任务 = 流水账风险。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 18. 知识库污染 / Knowledge Base Pollution Check
- **判定规则**：对照"定局锁"与 `story_frame.md` 的"世界法则"：新引入的设定是否与原有体系冲突、是否在没有交代的情况下新增矛盾规则（比"战力崩坏"更软性——是设定层面而非数字层面）。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 19. 视角一致性 / POV Consistency Check
- **判定规则**：检查视角切换是否有过渡、是否与设定视角一致。限制视角下不应突然跳到另一角色内心；全知视角下也应保持聚焦。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 20. 段落等长 / Paragraph Uniformity Check
- **判定规则**：连续多段是否出现明显均匀的段落长度（机器痕迹标志）。人类写作段落长度通常有节奏变化。
- **默认分级**：info（仅记录，不判定失败）
- **体裁覆写**：默认激活。

### 21. 套话密度 / Cliche Density Check
- **判定规则**：对照体裁高疲劳词 + 常见网文套话（"唇角微勾"、"眸光一沉"等）：是否出现高频重复表达。
- **默认分级**：info → 累计 ≥5 例 → 升级 warning
- **体裁覆写**：默认激活。

### 22. 公式化转折 / Formulaic Twist Check
- **判定规则**：转折是否来自"读者能提前 200 字猜到"的套路（如"关键时刻总有人闯入"、"临阵突破"无铺垫）。偶尔一次可接受；跨多章 = 节奏疲软。
- **默认分级**：warning
- **体裁覆写**：默认激活。

### 23. 列表式结构 / List-like Structure Check
- **判定规则**：连续章节的 chapter_summary 是否出现同构段落、同长度、同节奏——机器生成痕迹之一。人类写作行为节奏应更松散。
- **默认分级**：info
- **体裁覆写**：默认激活。

## 九、场景与空间

> 本节覆盖此前缺失的 **场景空间一致性**。网文最常见的槽点之一就是方位错乱：前一段"左厢房亮着灯"，同章就变成"右边的院落"；上一章还在山脚，下一章就俯瞰群峰，中间没有移动交代。

### 38. 空间一致性 / Spatial Consistency Check
- **判定规则**：对照 `current_state.md` 的「空间锚点 / Spatial Anchors」与本章已有描写，逐项核查：
  - **场景内**：同一场景内固定物件的位置（门在哪侧、桌椅方位、出入口朝向）在相邻段落间是否一致。
  - **人物相对方位**："A 在 B 的左手边"后文不能变成"右手边"，除非人物移动或转向已显式交代。
  - **移动路径连续**：角色从甲地到乙地，途经的空间（门廊 / 庭院 / 山路）不能瞬移跳过已建立的布局。
  - **视角与观察点**：全知/限制视角下，角色不应看到其位置不可能看到的内容（隔墙、背面、被遮挡物后方）。
  - **跨章场景**：返回旧场景时，其布局须与上次描写一致；改动须有显式事件（拆建、战斗破坏、重新布置）。
  - 质疑时引用"空间锚点 ID + 原文章节号 + 矛盾坐标"字面 token。
- **默认分级**：warning
- **体裁覆写**：★ 默认激活。动作 / 武侠 / 仙侠打斗场景 → **critical**（空间紊乱直接打戏读不懂）。现实向 / 悬疑 / 考据向 → **critical**。无纯静态对话的心理剧 → info。
- **降维建议**：若 `current_state.md` 尚未建「空间锚点」表，本轮先按本章描写自建一份，次轮起按表审计。

## 十、细节与道具

> 道具与细节数量不一致是 AI 写作的高频错误（"口袋里三样东西下一章变四样"仅其一例）。本节建立 **道具账本 + 跨场景追踪** 的硬性机制。

### 39. 道具追踪 / Prop & Detail Ledger Check
- **判定规则**：对照 `current_state.md` 的「道具账本 / Prop Ledger」逐项核查：
  - **数量守恒**：口袋/储物袋/背包内的物件数量，同一章内与跨章均以道具账本为硬边界——未交代获得/丢失/消耗，数量不可变化。
  - **存在性守恒**：甲章里"随身的玉佩"在乙章里不能凭空消失；要消失必须有显式事件（碎裂、赠人、被夺、典当）。
  - **状态守恒**：损坏/封印/开启/耗尽等状态，须以账本为准；修复/重充须有显式事件。
  - **名字统一**：同一道具全文使用同一名（不出现"青锋剑 / 青钢剑 / 那把剑"交替称呼同一件东西，除非角色视角有意为之）。
  - **跨章回溯**：审计须抽查最近 3–5 章的道具描述与账本对账，找出无痕变化。
- **默认分级**：warning（单次无痕 ±1 件）；跨 ≥3 章累计同类错误 → **critical**。
- **体裁覆写**：★ 默认激活。有随身储物/系统/经营要素的体裁 → **critical**。
- **配套文件**：本维的判定基础是 `current_state.md` 的「道具账本」表——见 templates.md。无表时，本轮必须先按前 3 章描写反建一份，再判后续。

### 40. 服装、外貌与随身物件 / Attire / Appearance / Carried Objects Check
- **判定规则**：作为维 39 的补充层（道具账本之外的穿戴/外貌层）：
  - **服装连续**：同一场景/连续时段内服装不可改变（除非显式更衣/战损/伪装）。"外袍"不能在中景里变成"长衫"。
  - **外貌特征**：发色 / 疤痕 / 纹身 / 胎记 / 饰品位置（左耳 / 右腕）以角色档案为准；跨章漂移须显式交代。
  - **替身/易容**：若外貌改变，必须存在对应的易容/夺舍/幻术手法在 `book_rules.md` 有定义且角色有能力使用。
  - 质疑时用"角色 + 章号 + 描写字面"三要素。
- **default severity**：info → 同角色累计 3 例跨章漂移 → warning。
- **体裁覆写**：默认激活。易容/伪装/身份悬疑向 → **critical**。

## 十一、常识与逻辑

> 本节覆盖此前缺失的 **非战力类常识**。战力逻辑已由维 4（战力崩坏）覆盖；本节专攻物理/生物/社会/因果常识。

### 41. 常识检查 / Common Sense Check
- **判定规则**：逐项核查情节是否违反该场景下的常识：
  - **物理可行性**：断臂之人能否挥剑、重伤者能否奔跑、水下能否点火（氧气）、高处坠落有无.buffer 物。
  - **因果时序**：未学剑者不能一剑封喉（除非已立"天赋异禀"伏笔且登记在案）、丹未出炉不能服用。
  - **社会常识**：称谓（对师长 / 对长辈 / 对敌对阵营）、礼仪（跪拜 / 作揖 / 拱手的使用场合）、制度（科举 / 继承 / 门派辈分）须与 `book_rules.md` 的"年代约束"一致。
  - **生物/物料**：毒发时间、火焰温度对材料的影响、饥渴极限——有明确先例时以先例为准，否则按现实常识判定。
  - 质疑时引用"违反的常识类型 + 原文 + 合理替代"三要素。
- **default severity**：warning；关键节点（生死 / 高潮 / 揭露）的常识错误 → **critical**。
